## 1. Project Overview

### 1.1 Mission

PPP is an AI-powered brand identity generation platform. Users upload multi-format inputs (PDFs, photos, sketches, text, URLs, notes) and the AI orchestrator processes them through specialized microservices to generate a complete visual identity — logos, color palettes, typography systems, brand guidelines, and a consolidated Brand Document.

### 1.2 Core Concept

Inspired by NotebookLM's document ingestion model, but applied to brand identity creation. The user feeds the system raw materials (mood boards, competitor PDFs, product photos, handwritten notes) and the AI synthesizes a coherent visual identity that can be refined interactively on a ReactFlow-based Sketch Board.

### 1.3 Target Users

- **B2B:** Teams and companies building or refreshing brand identity
- **B2C:** Individual creators and entrepreneurs
- **Single experience** — no tiered subscription gating

### 1.4 Monorepo Structure


## 2. Functional Scope

### 2.1 Input Processing

| Aspect | Detail |
|--------|--------|
| **Supported formats** | PDF, DOCX, PPTX, TXT, PNG, JPG, URLs, pasted text, manual notes |
| **File size limits** | Per-workspace `storage_bytes` quota (not per-file) |
| **Bulk upload** | Drag-and-drop UI implies multiple files; no explicit bulk logic documented |
| **Organization model** | `organization_id` → `workspace_id` hierarchy |
| **Processing trigger** | Automatic on upload: MinIO storage → NATS `workspace.source.process.requested` → RAG Worker (extraction, chunking, embeddings) |

### 2.2 Microservices (Backend/AI)

| Service | Responsibility |
|---------|----------------|
| **Document Extraction** | PDF, DOCX, PPTX parsing and text extraction |
| **Embedding + RAG Pipeline** | Chunking, vector embeddings, retrieval |
| **Model Routing** | AI model selection and orchestration |
| **Agent Management** | Worker lifecycle and task distribution |
| **Web Research/Crawling** | URL content extraction and analysis |
| **Export** | PDF, SVG, PNG, JPG generation |

### 2.3 Sketch Board (ReactFlow Canvas)

| Aspect | Detail |
|--------|--------|
| **Node types** | User-created: sticky note, text, heading, shape, frame. Source-derived: image, source card. RAG: citation card. AI: chat response, concept card, asset card. Structural: connector, group |
| **Drag from Results** | Yes — "Add result to board", "Add section to board", "Add citation to board" |
| **Connectors** | Yes — ReactFlow connectors for relational mapping (color palette → logo, direction → concept) |
| **Persistence** | Server-side, durable (canvas metadata, versions, snapshots managed by Dev 3 on NestJS) |
| **Version history** | Undo/redo + snapshots (workspace-snapshots MinIO bucket, canvas versions in DB) |
| **Scope boundary** | Canvas state management = Dev 3. AI side only produces output that lands on board |

**Node Registry:**

| Node Type | Source | Description |
|-----------|--------|-------------|
| `sticky-note` | User | Freeform text note |
| `text` | User | Rich text block |
| `heading` | User | Section heading |
| `shape` | User | Geometric shape |
| `frame` | User | Container/frame |
| `image` | Source upload | Uploaded image |
| `source-card` | Source upload | Document source reference |
| `citation-card` | RAG retrieval | Cited excerpt from source |
| `chat-response` | AI chat | Response from AI assistant |
| `concept-card` | AI generation | Generated brand concept |
| `asset-card` | AI generation | Generated brand asset (logo, palette, etc.) |
| `connector` | Structural | Relationship line between nodes |
| `group` | Structural | Node grouping container |

### 2.4 AI Chat

| Aspect | Detail |
|--------|--------|
| **Model** | Conversational, multi-turn dialogue with context |
| **Context access** | Full workspace context (all uploaded sources, board state) |
| **Board interaction** | Users can select board elements and ask AI to act on them (e.g., select logo → "make this more minimal") |
| **Draft preservation** | Drafts preserved on close |
| **History** | Persisted per workspace |

### 2.5 AI Output

| Output Type | Landing Target |
|-------------|----------------|
| Logos | Asset cards on board |
| Brand DNA | Brand Document artifact |
| Color palettes | Concept cards on board |
| Typography suggestions | Concept cards on board |
| Visual identity system | Compiled into Brand Document |

### 2.6 Brand Document

- Consolidated artifact aggregating all generated identity elements
- Exportable as compiled PDF/SVG/PNG/JPG
- Serves as the single source of truth for the generated brand

### 2.7 Export System

| Aspect | Detail |
|--------|--------|
| **Formats** | PDF, SVG, PNG, JPG |
| **Full export** | Complete Brand Document as compiled artifact |
| **Single element export** | Individual logos, palettes, or any board element |
| **Implementation** | jsPDF for PDF generation, worker service for heavy processing |

### 2.8 Sharing & Collaboration

| Aspect | Detail |
|--------|--------|
| **Sharing model** | Invited users only — no public links |
| **RBAC** | None |
| **External stakeholders** | No view/comment access without invitation |
| **Editor model** | Single editor (no multi-cursor real-time) |
| **Presence/cursors** | Frontend renders (backend state = Dev 3) |

### 2.9 Authentication

### 4.2 Typography

**Font Families:**
- Display: `SF Pro Display, system-ui, -apple-system, sans-serif`
- Body/UI: `SF Pro Text, system-ui, -apple-system, sans-serif`
- Fallback (non-Apple): `Inter` with `font-feature-settings: "ss03"`, tighter letter-spacing, reduced line-height

**Hierarchy:**

| Token | Size | Weight | Line Height | Letter Spacing | Use |
|-------|------|--------|-------------|----------------|-----|
| `{typography.hero-display}` | 56px | 600 | 1.07 | -0.28px | Hero headline |
| `{typography.display-lg}` | 40px | 600 | 1.10 | 0 | Tile headlines |
| `{typography.display-md}` | 34px | 600 | 1.47 | -0.374px | Section heads |
| `{typography.lead}` | 28px | 400 | 1.14 | 0.196px | Product tile subcopy |
| `{typography.lead-airy}` | 24px | 300 | 1.5 | 0 | Environment lead (rare 300) |
| `{typography.tagline}` | 21px | 600 | 1.19 | 0.231px | Sub-tile tagline |
| `{typography.body-strong}` | 17px | 600 | 1.24 | -0.374px | Inline strong emphasis |
| `{typography.body}` | 17px | 400 | 1.47 | -0.374px | Default paragraph |
| `{typography.dense-link}` | 17px | 400 | 2.41 | 0 | Footer link columns |
| `{typography.caption}` | 14px | 400 | 1.43 | -0.224px | Captions, button text |
| `{typography.caption-strong}` | 14px | 600 | 1.29 | -0.224px | Emphasized captions |
| `{typography.button-large}` | 18px | 300 | 1.0 | 0 | Store hero CTAs |
| `{typography.button-utility}` | 14px | 400 | 1.29 | -0.224px | Utility/nav buttons |
| `{typography.fine-print}` | 12px | 400 | 1.0 | -0.12px | Fine-print, footer |
| `{typography.micro-legal}` | 10px | 400 | 1.3 | -0.08px | Micro legal disclaimers |
| `{typography.nav-link}` | 12px | 400 | 1.0 | -0.12px | Global nav items |

**Principles:**
- Negative letter-spacing at display sizes (17px+)
- Body copy at **17px**, not 16px
- Weight 300 is rare and deliberate (button-large, lead-airy)
- Weight 600 for headlines (not 700)
- Weight 500 is **deliberately absent** (ladder: 300/400/600/700)
- Line-height is context-specific (1.07–2.41 range)

### 4.3 Spacing System

| Token | Value |
|-------|-------|
| `{spacing.xxs}` | 4px |
| `{spacing.xs}` | 8px |
| `{spacing.sm}` | 12px |
| `{spacing.md}` | 17px |
| `{spacing.lg}` | 24px |
| `{spacing.xl}` | 32px |
| `{spacing.xxl}` | 48px |
| `{spacing.section}` | 80px |

- Base unit: 8px
- Section vertical padding: 80px
- Card padding: 24px
- Button padding: 8–11px vertical, 15–22px horizontal

### 4.4 Border Radius

| Token | Value | Use |
|-------|-------|-----|
| `{rounded.none}` | 0px | Full-bleed tiles |
| `{rounded.xs}` | 5px | Inline chips (rare) |
| `{rounded.sm}` | 8px | Dark utility buttons, inline card imagery |
| `{rounded.md}` | 11px | Pearl Button capsules |
| `{rounded.lg}` | 18px | Store utility cards, accessories grid |
| `{rounded.pill}` | 9999px | Primary CTAs, search input, configurator chips |
| `{rounded.full}` | 50% | Circular control chips |

### 4.5 Elevation & Depth

| Level | Treatment | Use |
|-------|-----------|-----|
| Flat | No shadow, no border | Full-bleed tiles, nav, footer |
| Soft hairline | 1px `rgba(0,0,0,0.08)` border | Utility cards, sub-nav |
| Backdrop blur | `backdrop-filter: blur(N)` on Parchment 80% | Sub-nav, sticky bar |
| Product shadow | `rgba(0,0,0,0.22) 3px 5px 30px 0` | **Only** product renders on surfaces |

**Shadow philosophy:** Exactly ONE drop-shadow in the entire system — applied to product imagery only. Never on cards, buttons, or text.

### 4.6 Button Grammar

| Component | Background | Text | Rounded | Padding |
|-----------|------------|------|---------|---------|
| `button-primary` | `#0066cc` | `#ffffff` | pill | 11px × 22px |
| `button-secondary-pill` | transparent | `#0066cc` | pill | 11px × 22px |
| `button-dark-utility` | `#1d1d1f` | `#ffffff` | sm (8px) | 8px × 15px |
| `button-pearl-capsule` | `#fafafc` | `#333333` | md (11px) | 8px × 14px |
| `button-store-hero` | `#0066cc` | `#ffffff` | pill | 14px × 28px |
| `button-icon-circular` | `rgba(210,210,215,0.64)` | `#1d1d1f` | full (50%) | 44px × 44px |

**Active state:** `transform: scale(0.95)` — system-wide micro-interaction.

### 4.7 Do's and Don'ts

**DO:**
- Use `{colors.primary}` (#0066cc) for every interactive element — nothing else
- Set headlines with negative letter-spacing (`-0.28 → -0.374px`)
- Run body copy at 17px / 400 / 1.47 / -0.374px
- Alternate light/dark tiles — the color change IS the divider
- Reserve `{rounded.pill}` for primary CTAs and action elements
- Apply product-shadow only to product renders
- Use `transform: scale(0.95)` as active/press state on every button

**DON'T:**
- Don't introduce a second accent color
- Don't add shadows to cards, buttons, or text
- Don't use gradients as decorative backgrounds
- Don't set body copy at weight 500
- Don't round full-bleed tiles
- Don't tighten line-height below 1.47 for body copy
- Don't mix radius grammars (sm for compact, lg for cards, pill for CTAs)
- Don't use `{colors.primary-on-dark}` on light surfaces

### 6.3 Contract Gap (Known Issue)

| Aspect | Status |
|--------|--------|
| `@ppp/contracts` package exists | Yes — 11 JSON Schemas, TS types, Python models |
| Frontend imports `@ppp/contracts` | **No** — completely disconnected |
| Frontend API types | Independently defined in `src/lib/api/` |

**Impact:** Frontend types may diverge from backend/AI contract definitions. No CI enforcement.

**Mitigation for this project:** Reference `packages/contracts/` as the canonical type source. When creating new API integration code, prefer aligning with contract definitions even if import isn't wired yet.

## 7. ReactFlow Board Specification

### 7.1 Critical Constraint

> **ReactFlow must be preserved.** The sketch board generates a marketing flow after VI validation. Every component created serves as a resource to finalize the Visual Identity.

### 7.2 Board Capabilities

- **Node creation:** Drag from Results panel, context menu, AI placement
- **Node connections:** ReactFlow connectors for relational mapping
- **Selection:** Single/multi-select with keyboard modifiers
- **Context menu:** Right-click for node actions
- **Zoom/Pan:** Standard ReactFlow controls + minimap
- **Persistence:** Server-side via Dev 3 (canvas metadata, versions, snapshots)

### 7.3 Interaction Model

| Action | Source |
|--------|--------|
| "Add result to board" | Live AI Results panel |
| "Add section to board" | Live AI Results panel |
| "Add citation to board" | Live AI Results panel |
| Drag node to canvas | Results panel, source panel |
| Connect nodes | Board interaction |
| Context menu actions | Board interaction |
| AI placement | Chat response → concept/asset cards |

### 7.4 Post-VI Marketing Flow

After Visual Identity is validated on the board:
1. Board state is analyzed by AI orchestrator
2. Marketing flow is generated as a connected node graph
3. Components on the board become reusable resources
4. Flow can be exported (PDF/SVG/PNG/JPG)

## 15. Non-Negotiables

### 15.1 Design System Adherence

- **Single accent color:** `{colors.primary}` (#0066cc) for all interactive elements — no exceptions
- **Typography hierarchy:** SF Pro Display for headlines (600 weight, negative letter-spacing), SF Pro Text for body (400 weight, 17px)
- **Elevation rules:** Exactly ONE drop-shadow (product renders only). No shadows on cards, buttons, or text
- **Surface alternation:** Light/dark tile alternation as section divider — no borders or shadows for separation
- **Radius grammar:** pill for CTAs, sm for compact utility, lg for cards — no mixing

### 15.2 ReactFlow Preservation

- ReactFlow is the **core compositional engine** — must not be replaced
- Board generates marketing flow after VI validation
- Every component created serves as a resource for VI finalization
- Node types must support the full range of user-created, source-derived, RAG, and AI-generated content

### 15.3 Quality Bar

- Body copy at **17px**, not 16px — the extra pixel defines brand reading pace
- Weight ladder: **300/400/600/700** — weight 500 is deliberately absent
- Active state: `transform: scale(0.95)` on every button — system-wide micro-interaction
- Touch targets: Minimum 44×44px
- No decorative gradients — atmosphere comes from photography
- No rounded full-bleed tiles — rectangular and edge-to-edge
